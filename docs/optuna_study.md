# One Optuna study (Ticket 07)

The unchanged notebook's cell 15 defines `tune_model(name, T, n_trials=20)`.
It creates a new in-memory **minimize** study for one model and sequence
length, then uses the best completed trial's parameters. The notebook lets
Optuna generate the study name and does not persist a study database. The
extracted interface is `experiments.tune_model`; it returns the Optuna study
and a serializable record. `save_study_result(path, result)` writes that
record as JSON without retraining.

## Search and execution order

Every model uses the same three suggestions, in this order:

| Parameter | Optuna distribution |
| --- | --- |
| `lr` | `suggest_float(1e-4, 5e-2, log=True)` |
| `hidden_size` | `suggest_categorical([16, 32, 64])` |
| `init_method` | `suggest_categorical(["orthogonal", "xavier", "default"])` |

The sampler is `TPESampler(seed=42)` and the pruner is
`MedianPruner(n_startup_trials=5, n_warmup_steps=50)` with other Optuna
defaults. A study runs 20 trials by default. Each trial uses seed
`1000 + trial.number`, then calls the existing training function for 150
updates by default. The checked-in gate mode is `one`; gate bias is outside
the search space. The training function seeds Python, NumPy, and Torch before
CPU model construction and initialization, then draws fresh training batches
from the global Torch RNG. Validation is checked at the training module's
scheduled updates. The trial reports post-update validation MSE at those
steps and asks the median pruner whether to stop. Its objective is the
**final** validation MSE, not the best historical value. No test MSE enters
the objective. Trial failure and pruning follow Optuna's notebook defaults:
an uncaught objective exception stops `optimize`; a pruned trial is recorded
as pruned; a non-finite objective is recorded as failed. If no trial completes,
Optuna cannot provide a best trial and the function raises
`NoCompletedTrialError` (a `ValueError`) with the partial study and record on
its `result` attribute. This preserves the notebook's failure instead of
inventing a selected configuration.

The record includes the effective configuration and budgets, generated study
name, direction, actual Optuna trial distributions, sampler and pruner settings, trial seeds,
suggestions, intermediate reports, values and statuses, selected trial,
Python/Torch/Optuna versions, device, dtype, and notebook hash. Study names
are generated by Optuna and can differ across otherwise equivalent runs;
trial sequences and numerical observations are the reproducibility target.
