# Pre-extraction notebook baseline

The original notebook is committed unchanged in source snapshot `72418d9241b81e8ffefc73c917eab6663413cb10` with the approved specification and architecture. Its working-file and snapshot SHA-256 are both `71ec17cdb7fffcc39fef12bfe4977f75117ceedaa90c03109e79f51d98059f44`. This snapshot predates extraction of data, model, training, and experiment code.

The [fixture](../tests/fixtures/notebook_baseline.json) contains **22 directly executed, verified CPU cases**. It was generated by [the capture script](../scripts/capture_notebook_baseline.py), which checks the working notebook and committed snapshot hashes, then executes original code cells **3, 5, 7, 9, 11, and 13 in that order**. It calls the definitions from those cells. It does not copy their algorithms into the package or execute the notebook's full-grid cells. `CUDA_VISIBLE_DEVICES=-1` selects the reference CPU environment before cell 3 imports Torch; cell 3 sets `CUBLAS_WORKSPACE_CONFIG` and deterministic algorithms as written.

## Captured cases

| Cases | Direct observation | Scope |
| --- | --- | --- |
| `data_t10_seed7` | Global-RNG synthetic inputs/targets, zero tail, fixed validation/test sets and their full-tensor checksums | `T=10`, batch 4; fixed sets retain notebook size 2048 and seeds 10000/20000 |
| `vanilla_rnn_*`, `lstm_*`, `gru_*` model cases | Exact initial parameter arrays, predictions, final-step MSE, all hidden-state gradient norms, first/last input gradients, first parameter gradient; LSTM detached inspection states and GRU gate preactivations/activations | Each model at `T=1,10,30` in float32 and `T=30` in float64, batch 4, seed 7, gate mode `one` |
| `gru_gate_*`, `lstm_gate_chrono` | Target gate weights/biases, GRU Reset Gate bias, LSTM input-gate bias, post-initialization RNG digest | GRU `default`, `zero`, `one`, `chrono`, numeric retention bias `2.0`; LSTM `chrono`, seed 13 |
| `*_training_t10` | Three pre-step losses, post-step validation MSE, final-checkpoint test MSE, captured pre-clipping hidden gradients, short prediction sample, and evaluation-mode side effect | Each model, `T=10`, 3 optimizer updates, seed 0, notebook batch size 128 and fixed evaluation size 2048 |

The three-update training cases are **reduced probes**, not results from the notebook's 150-update tuning or 300-update final runs. They preserve the notebook's function body, fresh-batch order, optimizer, clipping, validation timing, and final-state evaluation. They do not verify Optuna selection, long-run learning outcomes, or the full experiment matrix. Those remain for later tickets. The full `T=30` backward cases show a nonzero gradient at the first hidden state; there is no truncated-BPTT window. The diagnostic driver marks input tensors `requires_grad` to observe input gradients, without changing the notebook's forward or backward equations. Training uses the notebook's ordinary inputs.

The captured GRU uses `W_z` as the **Update Gate linear layer** and `W_r` as the **Reset Gate linear layer**. Retention-bias mode `one` sets `W_z.bias` to `-1`, while the saved `W_r.bias` remains at constructor initialization. The fixture records the current `evaluate` side effect: a model put in evaluation mode enters training mode after `evaluate` returns. This is observed behavior, not a bug fix.

## Provenance and comparison

Each case records its source hash and cell IDs, source snapshot, configuration, seed and RNG call-order assumptions, input shape and representative values, precision, device, observed outputs, execution status, actual invocation, and an environment digest. The top-level environment records Python 3.13.0, the 38 exact dependency versions from `requirements-cpu.lock`, Torch `2.11.0+cpu`, CPU device, deterministic setting, CUDA settings, platform/processor, and Torch thread count. Each case and the complete fixture have a canonical JSON SHA-256 integrity digest. The capture command refuses to overwrite an existing fixture.

For a rerun in the **same pinned CPU environment**, compare initial parameter arrays exactly. Compare computed float32 values with `rtol=1e-5, atol=1e-6` and computed float64 values with `rtol=1e-8, atol=1e-10`, as predeclared in the approved specification. These tolerances allow small floating-point differences while retaining sensitivity to changed equations and update order. The [fixture test](../tests/test_notebook_baseline.py) reruns the original source, verifies schema/provenance/checksums, and compares its observations with the saved oracle. A future extracted module must be compared against this committed fixture; the fixture must never be regenerated merely to satisfy a failing regression test.

Saved output cells in the notebook are **historical, unverified observations**. They were not read as expected values or used to claim empirical reproduction. No case here establishes the full-grid results. A full matrix run and comparison remain Ticket 14.

To make a new capture in a separate location, from the pinned environment run:

```powershell
python scripts/capture_notebook_baseline.py --output path/to/new-baseline.json
python -m pytest tests/test_notebook_baseline.py -q
```
