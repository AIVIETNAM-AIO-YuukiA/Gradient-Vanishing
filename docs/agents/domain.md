# Domain docs

This repo uses a single-context layout: `CONTEXT.md` at the root and ADRs under `docs/adr/`.

Before exploring a domain area, read the root `CONTEXT.md` and any ADRs relevant to that area. If an ADR directory or relevant file is absent, proceed. Create glossary entries and ADRs when decisions are resolved, following the domain-modeling skill.

Use the glossary's terms in tickets, tests, proposals, and code discussions. If a needed term is missing or a proposed change conflicts with an ADR, surface that gap or conflict explicitly.
